פרויקט: Fridge List App — לפי Spec/Plan מקומיים; אימות חי חסום.

## Goal and conversation summary
כותרות קטגוריות דביקות עם כיווץ מתוך הגלילה. מקור: בקשות המשתמש בשיחה זו; מטרת הטיקט להעביר הנחיות מדויקות לאייג׳נט מפתח, בלי לבצע כאן פיתוח.

## Current behavior and evidence
מצב קיים: Partial. רוויזיית בסיס מקומית be6bfa6 עם שינויים לא מחויבים רבים; אינה הוכחה למצב main או production.
ראיות: src/components/CategorySection.tsx; src/hooks/useCollapsedSections.ts; src/workspace.css: shopping-list-scroll; src/components/SharedShoppingLists.tsx.
הדרישות החדשות הן מקור הסמכות; דוגמאות והצעות מימוש אינן יכולות להחליף קריטריונים מפורשים.

## Scope and classification
סוג: Enhancement. השינוי מוגבל לתוצאה המתוארת בקריטריונים; שינויים לא קשורים ושכתוב מערכת אינם חלק ממנו.

## Fit with Spec and Plan
הרחבת UX של רשימת הקניות; FR-02 ו־FR-12 משטחי תצוגה משותפים.
מסמכי הבסיס: docs/specs/spec-settings-sharing-feedback.md; docs/plans/plan-settings-sharing-feedback.md; docs/specs/DECISIONS.md. לא נערכו מסמכי Spec/Plan במהלך הכנת הטיוטה.

## Architecture and implementation guidance
לזהות את scroll container בפועל לפני position:sticky. לתחום כל כותרת למקטע שלה ולהגדיר top ו־z-index ביחס לבאנר. לשמר aria-expanded ו־aria-controls ולא לפגוע בסידור וגרירה קיימים.
יש לקרוא את נקודות הכניסה המפורטות בראיות ואת מודוליהן לפני קביעת חתימות ושמות חדשים. לא להמציא API קיים.

## Risk
Medium. שינוי חוצה תצוגות/מצב אסינכרוני ותחומי נתונים דורש רגרסיה ממוקדת.
GitNexus: QuickAddBar ו־CategorySection החזירו UNKNOWN; אינדקס behind בקומיט אחד. חיפוש קוד אישר שימוש בנתיבי הרשימה ובתצוגה המשותפת. UNKNOWN אינו Low ואינו הוכחה שאין callers. ניווט שיתופים נמדד קודם HIGH ולכן אין לשנות את הלוגיקה שלו בלי impact עדכני. לא נערך impact לכל נקודת כניסה בטיוטה; חובה לבצע לפני פיתוח.
מיתון: הגבלת scope, בדיקות מסלולים קיימים, שמירת אישור משתמש לפני כתיבה וסקירת diff. rollback: שחזור השינוי התחום בלי מחיקת נתוני משתמשים. הערכת הסיכון זמנית עד אימות גרסה חיה.

## Acceptance Criteria
1. כותרת הקטגוריה שבה נמצאים נשארת נגישה בגלילה ומאפשרת כיווץ בלי לחזור לתחילת הקטגוריה.
2. הכותרת הבאה מחליפה את הקודמת בלי הצטברות כותרות והסתרת תוכן; זו בחירת מימוש מוצעת לצורך הדרישה.
3. כיווץ ופתיחה פועלים במובייל, מחשב, RTL/LTR, מגע ומקלדת.
4. כותרות אינן חופפות לבאנר הרשימה המשותפת, לשדה ההוספה או לניווט.
5. פתיחת קטגוריות לצורך חיפוש אינה נכתבת בהכרח כהעדפת קיפול קבועה; ודא חזרה עקבית לאחר ניקוי החיפוש.

## Dependencies and agent execution order
לתאם עם טיוטה 01 וטיוטה 05; אין תלות ב־AI כדי לפתח את הגלילה.
סדר: קריאת מקור עדכני → פתרון שאלות/חוזים → impact → פיתוח תחום → בדיקות → סקירה → אינטגרציה → אימות שחרור אם נדרש. סימוני 01–07 הם שמות טיוטה מקומיים, לא מזהי Kan.

## Security and Privacy
לשמר scope לרשימה ולמשתמש המורשים. לא לחשוף הרשאות או רשימות פרטיות למקבל שיתוף. לא לרשום secrets או מידע מלא שאינו נחוץ לניתוח.

## Compatibility and Migration
לשמר RTL/LTR, מקלדת ומובייל, שמות קטגוריות מותאמים והעדפות שמורות. אין הרשאה למחיקת נתונים או migration אוטומטי. אם נדרש שינוי payload/storage, לתעד ולאמת תאימות לפני מימוש.
