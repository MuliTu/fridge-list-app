## Architecture and implementation guidance
הרצת השיחה הקודמת: 31 בדיקות ממוקדות ו־typecheck עברו; build נכשל בשלב prerender עם listen EPERM; architecture check דיווח על 8 הפרות בקבצים אחרים. אלו ראיות היסטוריות מקומיות בלבד ויש להריץ מחדש בסביבה המתאימה. יש הרשאת משתמש קודמת למיזוג ולייב, אך כתיבת טיקט עצמה אינה ראיית ביצוע.
יש לקרוא את נקודות הכניסה המפורטות בראיות ואת מודוליהן לפני קביעת חתימות ושמות חדשים. לא להמציא API קיים.

## Risk
High. שחרור פרודקשן עלול להשפיע על נתונים ומשתמשים ודורש ראיות ויכולת שחזור.
GitNexus: QuickAddBar ו־CategorySection החזירו UNKNOWN; אינדקס behind בקומיט אחד. חיפוש קוד אישר שימוש בנתיבי הרשימה ובתצוגה המשותפת. UNKNOWN אינו Low ואינו הוכחה שאין callers. ניווט שיתופים נמדד קודם HIGH ולכן אין לשנות את הלוגיקה שלו בלי impact עדכני. לא נערך impact לכל נקודת כניסה בטיוטה; חובה לבצע לפני פיתוח.
מיתון: הגבלת scope, בדיקות מסלולים קיימים, שמירת אישור משתמש לפני כתיבה וסקירת diff. rollback: שחזור השינוי התחום בלי מחיקת נתוני משתמשים. הערכת הסיכון זמנית עד אימות גרסה חיה.

## Acceptance Criteria
1. למפות כל שינוי מבוקש לענף, commit, בדיקות וגרסה; להפריד קוד מקומי, ממוזג ומפורסם.
2. להשלים build כולל prerender, typecheck, בדיקות ממוקדות ובדיקות הרשאות/רגרסיה נדרשות.
3. לפתור או לתעד באופן מבוסס חסמי architecture check בלי להחליש אותו; אין להציג build שנכשל כעובר.
4. לבצע GitNexus detect_changes ללא partial/truncated ולבדוק השפעה לפני commit; לא לערב שינויים מקומיים לא קשורים.
5. להציג ראיית deployment מוצלח וגרסה, ואז לבדוק את מסך הרשימה המשותפת האמיתי במחשב ובמובייל עם בעלים ומקבל מורשים.
6. לוודא בלייב שהבאנר, הקטגוריות, הכפתורים והרוחב קיימים; תצוגת פיתוח לא מספיקה.
7. לתעד rollback לגרסה הקודמת; לא לסמן Done על סמך מיזוג או בקשת פריסה בלבד.
